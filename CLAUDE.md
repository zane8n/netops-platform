# Netrune

Local-first network operations console: inventory, topology, VLAN
management, diagnostics, backups, and a deterministic natural-language
query layer, all as one CLI (`netrune`, with `netops`/`netop` as compatible
aliases). Python 3.11+, no server, no daemon (the traffic collector is the
one exception -- a separate `systemd` unit, not something `netrune` itself
stays resident for).

## Where things live

- `netops_platform/core.py` -- `App` (dispatch, shared CLI infra, ~15
  smaller domains directly on the class) and `State` (the SQLite layer).
  Six larger domains are mixin classes composed onto `App`, each in its own
  file: `device_cli.py`, `inventory_cli.py`, `vlan_cli.py`,
  `topology_cli.py`, `lookup_cli.py`, `diagnose_cli.py`. The other
  `*_cli.py` domain modules are free functions with a
  `dispatch(app, args, opts)` entry point (e.g. `traffic_cli.py`).
- `netrune/` -- thin re-export shims (`sys.modules[__name__] = _implementation`)
  pointing at `netops_platform/`, the real implementation. Deliberate v8
  compatibility-window design, not duplication to clean up.
- `ai/` -- a separate, standalone local-AI wrapper layer (Ollama-optional,
  currently `qwen3:8b`) that calls only the public `netrune` CLI through an
  approved-workflow allowlist (`ai/config/tools.yaml`). Not part of
  `netops_platform`; doesn't import it.
- `docs/CLAUDE_REFERENCE.md` -- **the exhaustive technical reference**:
  every command's exact syntax/validation/side-effects/output shape/exit
  codes, the full data model, goal-oriented command recipes. Load this on
  demand for any question deeper than what's below. Written for exactly
  this purpose -- read it before guessing at command behavior.
- `docs/NETRUNE_TOOLSET_HANDBOOK.md` -- the human-facing operator manual
  (5,000+ lines). Prose walkthroughs and usage guidance rather than exact
  internal behavior.
- `docs/adr/` -- architecture decision records. Superseded decisions get a
  `> **Superseded YYYY-MM-DD.**` annotation at the top rather than being
  deleted or silently rewritten -- check here before assuming an ADR's
  decision is still current.
- `docs/reference/command-registry.json` -- the machine-generated, always-
  current source of truth for every registered command's exact syntax,
  args, and safety metadata. Regenerated by `scripts/generate_reference.py`.

## Architecture in one paragraph

One process per invocation. `App.dispatch(argv)` parses global flags,
routes on the first positional arg (the domain) to one of 27
`cmd_<domain>` handlers via a flat dict, which routes internally on the
second arg (the verb). Every command returns an int exit code (0=success,
see `docs/CLAUDE_REFERENCE.md` section 3 for the full table). State lives
in one SQLite database per profile; `command_registry()` is the single
source of truth for every command's syntax, driving CLI dispatch,
generated docs, completions, and man pages together, so it can't drift.
Config-changing commands follow a guarded preflight/backup/apply/verify/
audit lifecycle (ADR 0005) -- `--dry-run` to preview, `--confirm` to apply,
never skip straight to `--confirm` on an unfamiliar change.

## Working in this repo

- **Tests:** `.venv/bin/python -m pytest -q` (full suite).
- **Doc/completion drift check:** `PYTHONPATH=. .venv/bin/python scripts/generate_reference.py --check`
  -- must pass after any change to `command_registry()`, `HELP_TOPICS`, or
  anything that affects generated docs/completions/man pages.
- **Secret/PII scan:** `PYTHONPATH=. .venv/bin/python scripts/privacy_check.py --root .`
- **Build + smoke test:** `python -m build`, then
  `bash scripts/smoke_wheel.sh dist/*.whl` and
  `bash scripts/smoke_install.sh dist/*.whl`.
- Run all of the above after any change that touches command behavior,
  output rendering, or packaging -- not just tests. This project treats a
  green test suite as necessary but not sufficient.
- Prefer verifying live behavior (a real invocation, ideally through a real
  pty when terminal rendering is involved) over trusting that code "should"
  work. Several real bugs this session were only caught this way, not by
  the test suite.

## Conventions worth knowing before changing code

- New domain logic: mixin class in its own file if it's called into from
  *other* parts of the class (needs MRO to keep every `self.foo(...)` call
  site working unmodified); free functions with a `dispatch(app, args,
  opts)` entry point if it has exactly one caller boundary. Don't guess --
  grep for external callers first, including in `tests/*.py`, not just
  other `netops_platform/*.py` files (a real miss this session: two ask.py
  functions turned out to be called directly by dozens of test sites, not
  just internally).
- A helper used by two or more domains, or by code outside the domain being
  touched, stays in `core.py` rather than moving with either domain.
- Every extracted/moved module needs a matching `netrune/<name>.py` shim
  (see existing ones for the exact 6-line pattern) -- a module without one
  fails `tests/test_netops_platform_85.py`'s alias-completeness check.
- ADR supersession, not deletion: when a documented decision changes, add a
  `> **Superseded YYYY-MM-DD.**` blockquote and update the `Status:` line;
  don't rewrite history.
